## Changes Implemented

Three route components were corrected against the real `eidolons.mcp.lock` and `roster/index.yaml` shapes. A shared parser library was extracted.

**McpStoreRoute** (`src/routes/McpStoreRoute.tsx`): interfaces replaced from the imagined `{ servers: Record<string, McpServerEntry> }` shape to the real shape: top-level key `mcps` is an array where each entry carries `name`, `kind`, `version`, `source.repo`, `target`, `hosts_wired[]`, and `installed_at`. The render path now iterates `mcps[]` and displays all fields. Empty-state copy corrected to "No MCP servers installed in this project."

**HarnessRoute** (`src/routes/HarnessRoute.tsx`): primary read changed from the non-existent `.eidolons/harness/manifest.json` to `eidolons.mcp.lock` (finds the entry where `name === "junction"`). The legacy sidecar path is now a fallback-only: if present, its `features` and `health` fields render under a "Sidecar details" sub-section. Not-found state now checks both sources and displays clear install instructions.

**RosterRoute** (`src/routes/RosterRoute.tsx`): the minimal YAML line parser was corrected. The real roster uses `eidolons:` as the top-level array key (not `members:`), and each item is a list entry `  - name: atlas` (not a keyed block `  atlas:`). The parser now detects `eidolons:` and matches `^\s+-\s+name\s*:\s*` for item starts.
